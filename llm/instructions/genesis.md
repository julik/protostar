We are doing a project called "protostar". The brief is to liberate Ruby developers from the weight of overdone, bloated, binary, heavy Google protobuf libraries. Here is what we are going to be building:

* A pure ruby protobuf compiler to replace protoc, just for compiling proto files into Ruby files which can then be used by protostar itself. We need full and complete v2 and v3 support, a proper parsing/lexing thing, we will steal all the test cases used by native protoc, and we will emerge with a nimble, pure-Ruby .proto-to-.rb transformer
* A pure ruby bufferizer/debufferizer, that is: a marshaler/unmarshaler for protobufs. This marshaler/unmarshaler has to support proto Message serialization and unserialization, proto message introspection and proto shape introspection. It should pass the unknown fields and byteloads unscathed on the way through. It should also be economical in storage - a single proto Message should be just a Ruby string, or an IO::Buffer if the host system supports it. Accesses should be lazy unless explicitly asked otherwise by the user. The contained messages should be able to access this "byte bag" through the message that contains them - but we also need to allow for convenient attribute/field access and a good inspect(). Both serialization and unserialization should be very straightforward, streaming insofar protobufs allow it, and not use any platform-native gems or libs.
- Encoding and decoding of proto messages must be Ractor-friendly, protobuf descriptors must be Ractor-shareable for maximum reuse and savings of memory
- We can - as the first phase - avoid the "1 buf for the entire message" if a message is not readonly - and parse it out into bags that we then reassemble to serialize. Maybe doing it that way initially is wiser.
* An adapter layer that allows protostar to be used INSTEAD of the Google protobuf libraries junk within their GRPC-based gems and grpc in general, using the new Bundler "override" feature - where you can force-replace a gem with your own. We should thus expose a full set of Ruby modules allowing full interop for any library using standard Google protobuf libraries to use us instead, with full support for message descriptor DLSLs post-compilation, marshaling/unmarshaling and the like. This should come as the last step.
* As one of our use cases - fork https://github.com/cheddar-me/pbbuilder and examine all the terror and suffering it had to go through, and think about how a better API could be exposed to it to achieve the same effect.

The end objective: any use of protobufs in a Ruby and/or Rails application should be able to not have the user install Google's abandonware nor protoc, but allow just grabbing the protostar. Idem for if poor people are forced to use grpc - we provide a complete and thorough protobuf encoding and decoding solution.

Give this a hard think, ask me questions if decisions need to be made. Generate a plan into an artefact I will sign off on. Once we are done with decisions, split this work into workstreams and delegate to Opuses to execute. Feel free to work with dependencies - for example, I think we need the compiler first, then the encoder/decoder, then the rest - but feel free to disagree. We do not have to prodice it in an hour's time: comprehensive over quick. Compatibility is minimum Ruby 3.x.

The crown jewel is the last item of course - and the most difficult.
