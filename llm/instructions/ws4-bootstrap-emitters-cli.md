# WS4: bootstrap, emitters and the CLI

Make the compiler produce things people use: Ruby files that define message classes,
gRPC service stubs, RBS signatures, `FileDescriptorSet` bytes, protoc-shaped `_pb.rb`
files, a `protostar` command and a `protoc-gen-protostar` plugin. Also close the loop on
`descriptor.proto`: our own compilation of it, committed, so descriptors can be read from
and written to bytes. Read `ws1`, `ws2`, `ws3` specs and the WS1, WS2, WS3 reports first.

## Deliverables

- `lib/protostar/dsl.rb`: the runtime DSL that generated files call (below).
- `lib/protostar/google/protobuf/*_pb.rb`: our generated files for `descriptor.proto`,
  `compiler/plugin.proto` and the well-known types (`any`, `api`, `duration`, `empty`,
  `field_mask`, `source_context`, `struct`, `timestamp`, `type`, `wrappers`), committed,
  with a Rake task `bootstrap:check` that regenerates them with the compiler and fails on
  any difference, and `bootstrap:regenerate`.
- `lib/protostar/schema/proto.rb`: `Schema::File#to_proto` (a
  `Google::Protobuf::FileDescriptorProto` message from our bootstrap classes, custom
  options encoded as extension bytes), `Schema::Builder.from_proto(message, pool:)` (the
  reverse, extension bytes in options decoded into `:__extensions` by looking the
  extensions up in the pool, unknown ones kept under `:__unknown_fields`),
  `Protostar.load_descriptor_set(bytes, pool:)` and `Protostar::Pool` conveniences, and
  `Protostar.generated_pool`, the process-wide pool generated files register into.
- `lib/protostar/compiler/emitters/{ruby,google_ruby,rbs,grpc,descriptor_set}.rb`.
- `exe/protostar` and `exe/protoc-gen-protostar`, with `lib/protostar/cli.rb` and
  `lib/protostar/plugin.rb`.
- Tests under `test/emitters/`, `test/cli/`, `test/bootstrap/`; goldens you make with
  outside tools under `test/corpus/generated/` with the script that made them.

## The generated Ruby format

Readable, diffable, no serialized blob. One file per `.proto`, named like protoc's Ruby
generator names it (`foo/bar.proto` to `foo/bar_pb.rb`), requiring the files of its
imports by the same rule. Shape:

```ruby
# frozen_string_literal: true
# Generated by protostar from foo/bar.proto. Do not edit.

require "protostar"
require "google/protobuf/timestamp_pb"

Protostar::DSL.file("foo/bar.proto", package: "acme", syntax: :proto3,
  dependencies: ["google/protobuf/timestamp.proto"], options: {java_package: "com.acme"}) do |f|
  # A person. Leading comments from the .proto come along as comments here.
  f.message "Person" do |m|
    m.field :name, 1, :string
    m.field :id, 2, :int32, json_name: "personId"
    m.field :friends, 3, :message, ".acme.Person", label: :repeated
    m.field :created_at, 4, :message, ".google.protobuf.Timestamp"
    m.oneof :contact do |o|
      o.field :email, 5, :string
      o.field :phone, 6, :string
    end
    m.map :attrs, 7, :string, :string
    m.enum "Kind" do |e|
      e.value :UNKNOWN, 0
      e.value :HUMAN, 1
    end
    m.reserved 100..199, "old_name"
  end
  f.service "Greeter" do |s|
    s.rpc :SayHello, ".acme.Person", ".acme.Person", server_streaming: true
  end
end

module Acme
  Person = Protostar::DSL.message("acme.Person")
  Person::Kind = Protostar::DSL.enum("acme.Person.Kind")
  Greeter = Protostar::DSL.service("acme.Greeter")
end
```

`Protostar::DSL.file` builds the descriptor hash, `Schema::Builder.build`s it against
`Protostar.generated_pool`, adds it, and defines the classes with `Types.define`.
Loading the same file twice is a no-op. Everything the hash can hold has a DSL spelling:
every option (known ones as keywords, custom ones under `extensions:`), `proto3_optional`,
features and editions, extensions and `extend`, extension ranges with options, reserved
names and ranges, enum aliases, deprecated flags. The DSL is also pleasant to write by
hand, so test it as a public API.

Ruby constant names follow protoc's Ruby generator exactly: `ruby_package` option wins,
else the package is split on dots and each part is camel-cased (`foo_bar.baz` to
`FooBar::Baz`); nested messages and enums become constants of their parent class; names
protoc would uppercase or prefix get the same treatment. Compatibility of these names
with grpc's generated stubs and with existing application code is the point.

## Other emitters

- **Google-format Ruby** (`--google_out`): the file protoc's Ruby generator would emit,
  serialized descriptor string, `pool.add_serialized_file`, `lookup(...).msgclass`
  constants and all. The corpus has protoc's own output for the four
  `compiler/ruby/*.proto` files; match it byte for byte.
- **RBS** (`--rbs_out`): what protoc's `rbs_generator.cc` emits; the corpus has its output
  for the same four files, match it byte for byte, and emit the same for our native
  format (the classes have the same shape).
- **gRPC** (`--grpc_out`): `foo/bar_services_pb.rb` as the `grpc-tools` gem emits it
  (`GRPC::GenericService`, `marshal_class_method = :encode`, `unmarshal_class_method =
  :decode`, `service_name`, `rpc :Name, Req, stream(Resp)`, `Stub = Service.rpc_stub_class`).
  Install `grpc-tools` once, generate goldens for `ruby/tests/service_test.proto` and
  one of your own protos covering every streaming combination, commit them under
  `test/corpus/generated/` with the script, and match them.
- **FileDescriptorSet** (`--descriptor_set_out`, `--include_imports`,
  `--include_source_info`): bytes via `to_proto` and our codec. For every corpus file,
  compiled with source info and imports, the bytes must equal the `.binpb` golden. If
  byte equality fails for a reason protoc's serializer owns (field ordering of extensions
  versus known fields, for instance), decode both with our codec and compare hashes, and
  explain the byte difference in the report.

## CLI and plugin

`protostar compile` takes protoc's flag names: `-I`/`--proto_path` (repeatable),
`--ruby_out=DIR`, `--google_out=DIR`, `--rbs_out=DIR`, `--grpc_out=DIR`,
`--descriptor_set_out=FILE`, `--include_imports`, `--include_source_info`,
`--error_format`, file arguments resolved against the include paths, bundled includes
last. Exit 1 with protoc-shaped diagnostics on stderr on failure. `protostar --version`.
No option parser gems; use `OptionParser`.

`protoc-gen-protostar` reads a `CodeGeneratorRequest` on stdin (our bootstrap classes
decode it), honours `parameter` for `grpc`, `rbs` and `google` output selection, and
writes a `CodeGeneratorResponse` with the files and `supported_features` set for proto3
optional and editions. Since protoc sends already-built `FileDescriptorProto`s, the
plugin goes through `Builder.from_proto`, not the parser.

## Testing

- Bootstrap: `bootstrap:check` passes; `descriptor_pb.rb` loads and defines
  `Google::Protobuf::FileDescriptorProto` and friends under the native runtime; every
  `.binpb` golden decodes through `load_descriptor_set` into files whose `to_h` equals
  the golden `.json` plus source info (tier B with our own codec, no oracle needed).
- Native emitter: for every corpus file, emit, load the output in a subprocess with a
  fresh pool, and assert the loaded `File#to_h` equals the golden hash and that the
  expected constants exist. Emit once more from the loaded file and assert the text is
  identical (the emitter is deterministic and the DSL round-trips).
- Google-format and RBS: byte equality with the four corpus goldens.
- gRPC: byte equality with the committed `grpc-tools` goldens.
- Descriptor set: byte equality with the `.binpb` goldens as above.
- CLI: subprocess runs over a small project in `test/fixtures/`, every flag, error
  output and exit codes. Plugin: a hand-built request through stdin.

## Out of scope

The google-protobuf facade (the Google-format emitter only writes files; running them
needs WS6's shim), JSON and text (WS5), conformance.
