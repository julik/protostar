# Generated Ruby that linters leave alone

**Status:** feature lead from Julik, 2026-10-06. Small, not scheduled.

> Linters reformatting generated code is always such an incredible pain in the butt.

## Today

Generated files begin with `# frozen_string_literal: true` and a "Generated by protostar
... Do not edit." comment, and nothing else. A project running RuboCop or Standard over
`lib/` or `app/` will lint them, autocorrect them, and then the next `protostar compile`
produces a diff again. The project's own `.standard.yml` ignores its generated files by
path, which is the workaround everyone ends up with.

## Wanted

Every generated Ruby file (`_pb.rb`, `_services_pb.rb`, the Google-format `_pb.rb` only if
protoc's goldens allow it, which they do not, so that one stays as protoc writes it) is
wrapped so that the common linters skip it without any project configuration:

```ruby
# frozen_string_literal: true

# Generated by protostar from acme/person.proto. Do not edit.
# rubocop:disable all
# standard:disable all

...

# rubocop:enable all
# standard:enable all
```

- `rubocop:disable all` / `rubocop:enable all` is what RuboCop documents for generated
  code and is honoured by Standard too; the `standard:` form is added for readers who grep
  for it and for Standard versions that scope the directive. Check what the current Standard
  release honours and keep only what is needed.
- The magic comment stays first, as Ruby requires; the disables come after the "Generated
  by" line so the file still opens with what it is.
- `# frozen_string_literal: true` stays on by default. Add `--no-frozen-string-literals`
  for the one project in a thousand that needs mutable literals in generated code, and
  make sure the emitters never rely on literal mutability themselves.
- Sorbet: generated files get `# typed: ignore`? No: with the `.rbs` emitted by default
  (`rbs-by-default.md`) Sorbet users convert signatures from RBS; a `# typed:` sigil would
  be wrong more often than right. Leave Sorbet to the RBS.
- The RBS files need no guard; nothing reformats them.
- The emitted gRPC stubs get the same wrapper. The `grpc-tools` goldens compare our
  `_services_pb.rb` byte for byte against grpc-tools' output, so the wrapper must be
  applied only in the protostar-native mode, or the goldens are re-recorded with a note.
  Decide when implementing; the safer path is a flag that the native CLI turns on and the
  golden tests turn off.
- Our own generated files (bootstrap, conformance, examples) regenerate with the wrapper,
  and `.standard.yml` can drop its path ignores as proof that the guard works.

## Effort

Small: a header and footer in `Emitters::Ruby` and `Emitters::Grpc`, one flag, the
regenerations, a test that the first lines of every emitted file are exactly these.
