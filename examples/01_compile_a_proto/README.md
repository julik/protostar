# Compile a proto

You have a `.proto` file and you want Ruby classes for it. protostar compiles it
itself. No protoc, no native extensions.

## Set up

Put protostar in a Gemfile.

```ruby
# examples/01_compile_a_proto/Gemfile
# frozen_string_literal: true

source "https://rubygems.org"

gem "protostar", path: "../.."
gem "rake"
```

In your project you would write `gem "protostar"`. Rake is only here for the last step.

```console
$ bundle install
```

## Write the schema

A `.proto` file describes messages: named fields, each with a type and a number.
The numbers go on the wire, the names do not.

```proto
// examples/01_compile_a_proto/orders.proto
syntax = "proto3";

package shop;

// An order as the checkout service records it.
message Order {
  string id = 1;
  string customer_email = 2;
  repeated LineItem items = 3;
  Status status = 4;
}

// One product in an order.
message LineItem {
  string sku = 1;
  uint32 quantity = 2;
  // Price of one unit, in cents.
  int64 unit_price_cents = 3;
}

enum Status {
  STATUS_UNSPECIFIED = 0;
  STATUS_PLACED = 1;
  STATUS_SHIPPED = 2;
}
```

## Compile it

```console
$ bundle exec protostar orders.proto > orders_pb.rb
```

protostar prints the Ruby for one file, and `>` puts it in `orders_pb.rb` next to
the proto. Errors, if any, go to the terminal and leave the file empty.

If you know protoc, its flags work too, and write the same file:

```console
$ bundle exec protostar compile -I . --ruby_out=. orders.proto
```

It prints nothing. `-I` is where imports are looked up, `--ruby_out` is where the
Ruby goes, and it takes several protos at once. Next to `orders_pb.rb` it also
writes `orders_pb.rbs` (RBS signatures, for Steep and editors) and `orders_pb.rbi`
(for Sorbet); `--no-rbs` and `--no-rbi` leave them out.

## Read what it wrote

Open `orders_pb.rb`. It is meant to be read.

```ruby
# examples/01_compile_a_proto/orders_pb.rb
# frozen_string_literal: true
# typed: ignore

# Generated by protostar from orders.proto. Do not edit.

require "protostar"

Protostar::DSL.file("orders.proto", package: "shop", syntax: :proto3) do |f|
  # An order as the checkout service records it.
  f.message "Order" do |m|
    m.field :id, 1, :string
    m.field :customer_email, 2, :string
    m.field :items, 3, :message, ".shop.LineItem", label: :repeated
    m.field :status, 4, :enum, ".shop.Status"
  end
  # One product in an order.
  f.message "LineItem" do |m|
    m.field :sku, 1, :string
    m.field :quantity, 2, :uint32
    # Price of one unit, in cents.
    m.field :unit_price_cents, 3, :int64
  end
  f.enum "Status" do |e|
    e.value :STATUS_UNSPECIFIED, 0
    e.value :STATUS_PLACED, 1
    e.value :STATUS_SHIPPED, 2
  end
end

module Shop
  Order = Protostar::DSL.message("shop.Order")
  LineItem = Protostar::DSL.message("shop.LineItem")
  Status = Protostar::DSL.enum("shop.Status")
end
```

The block is the schema, field for field, comments included. The constants at the
bottom are your classes: the package `shop` became the module `Shop`. Commit this
file. Your app loads it and never needs the compiler at runtime.

## Use it

Load the generated file.

```ruby
# examples/01_compile_a_proto/run.rb
# frozen_string_literal: true

require "bundler/setup"
require_relative "orders_pb"
```

Build a message. Fields are keyword arguments, enums are Symbols.

```ruby
# examples/01_compile_a_proto/run.rb
order = Shop::Order.new(
  id: "A-1001",
  customer_email: "ada@example.com",
  status: :STATUS_PLACED,
  items: [Shop::LineItem.new(sku: "MUG-01", quantity: 2, unit_price_cents: 1250)]
)
```

Look at it, read a field, and see how small it gets on the wire.

```ruby
# examples/01_compile_a_proto/run.rb
puts order.inspect
puts order.items.first.unit_price_cents
puts order.encode.bytesize
```

```console
$ ruby run.rb
#<shop.Order id: "A-1001", customer_email: "ada@example.com", items: [#<shop.LineItem sku: "MUG-01", quantity: 2, unit_price_cents: 1250>], status: :STATUS_PLACED>
1250
42
```

## Compile from Rake

Once there are a few protos, let Rake keep the generated files fresh.

```ruby
# examples/01_compile_a_proto/Rakefile
# frozen_string_literal: true

rule "_pb.rb" => ->(target) { target.sub(/_pb\.rb\z/, ".proto") } do |t|
  sh "protostar", "compile", "-I", ".", "--ruby_out=.", t.source
end

desc "Compile every .proto here into a _pb.rb next to it"
task protos: FileList["*.proto"].pathmap("%X_pb.rb")
```

Rake compiles a proto only when it is newer than its `_pb.rb`. After you edit
`orders.proto`:

```console
$ bundle exec rake protos
protostar compile -I . --ruby_out=. orders.proto
```

## If your team is still on protoc

protostar ships a protoc plugin too. `bundle exec protoc -I . --protostar_out=. orders.proto`
writes the same `orders_pb.rb`.

## Other outputs

`--grpc_out=DIR` writes gRPC service stubs (`*_services_pb.rb`) for protos with
`service` blocks. `--rbs_out=DIR` and `--rbi_out=DIR` put the signatures somewhere
other than next to the Ruby (a `sig/` or `sorbet/rbi/` tree); next to `--google_out`,
or alone, they describe google-protobuf's classes instead. `protostar --help` lists the rest.
